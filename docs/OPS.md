# Мониторинг и бэкапы

Всё присылается в один Telegram-бот: тревоги, ежедневный бэкап и (когда подключён вход в админку) уведомления о входах. Без бота мониторинг и бэкапы всё равно работают: пишут в журнал сервера и кладут копии на диск.

## Как это устроено

- **Мониторинг** (`server/monitor.mjs`, таймер раз в минуту): сайт снаружи (`https://atelierai.ru/api/health`), API на сервере, сервис распознавания фото, свободное место на диске (тревога при меньше 15% или меньше 3 ГБ), запись в каталог данных, срок TLS-сертификата (тревога при меньше 14 дней). Тревога приходит после двух неудач подряд, одно сообщение «упало» и одно «восстановилось» с длительностью простоя, пока лежит, напоминание раз в 6 часов. Состояние в `data/monitor-state.json`.
- **Бэкап** (`server/backup.mjs`, каждую ночь в 04:00 по Москве): архив `db.json`, `events.jsonl` и папки `photos/`, зашифрованный AES-256-GCM. Лежит на сервере в `/opt/atelier/backups` (14 последних) и приходит в Telegram с подписью: дата, размер, сколько пользователей, новых за сутки, платежей за сутки. **В Telegram уходит только зашифрованный архив**, почты и переписка в открытом виде сервер не покидают. Если архив больше 45 МБ, в Telegram придёт сообщение, а копия останется на сервере.

## Подключить бота (один раз, 5 минут)

1. В Telegram найди **@BotFather**, отправь `/newbot`, придумай имя и логин бота. Он пришлёт токен вида `123456:ABC...`, никому его не показывай.
2. Зайди на сервер: `ssh atelier`.
3. Запусти скрипт: `bash /opt/atelier/set-ops.sh`. Вставь токен (при вводе он не виден).
4. Скрипт попросит открыть бота в Telegram и отправить ему `/start`, после этого сам найдёт твой чат и пришлёт тестовое сообщение.
5. Скрипт покажет **ключ шифрования бэкапов**. Сохрани его в менеджер паролей сразу, вне сервера. Если сервер погибнет, а ключа не будет, бэкапы не расшифровать никому. Позже ключ можно посмотреть командой `grep BACKUP_PASSPHRASE /opt/atelier/server/.env` (на сервере).
6. Скрипт предложит сделать первый бэкап сразу, согласись: файл должен прийти в Telegram.

## Проверить руками

```
sudo systemctl start atelier-backup        # сделать бэкап сейчас
sudo systemctl start atelier-monitor       # один прогон мониторинга
journalctl -u atelier-backup -n 20 --no-pager
journalctl -u atelier-monitor -n 20 --no-pager
systemctl list-timers | grep atelier       # когда следующий запуск
ls -la /opt/atelier/backups
```

## Восстановить из бэкапа

1. Скачай `.enc`-файл из Telegram (или возьми из `/opt/atelier/backups`) и положи рядом с `server/backup-decrypt.mjs`.
2. Расшифруй (пароль спросит скрыто, это ключ из менеджера паролей): `node server/backup-decrypt.mjs atelier-20261120-0400.tar.gz.enc restored.tar.gz`
3. Останови сервис: `sudo systemctl stop atelier-api`
4. Распакуй в каталог данных (старое сначала убери): `sudo -u atelier tar -xzf restored.tar.gz -C /opt/atelier/server/data`
5. Запусти: `sudo systemctl start atelier-api`, проверь `https://atelierai.ru/api/health`.

Ключ можно передать и переменной: `BACKUP_PASSPHRASE=... node server/backup-decrypt.mjs ...`. Если файл не расшифровывается («Неверный пароль или файл повреждён»), проверь, что ключ скопирован целиком и файл скачан полностью.

## Ограничения

- Мониторинг работает на самом сервере, поэтому **не увидит падение всего сервера** (выключили, пропала сеть, закончились деньги на хостинге). Заведи бесплатный внешний пинг, например UptimeRobot: монитор HTTPS на `https://atelierai.ru/api/health`, оповещение на почту или в Telegram.
- Ключ шифрования хранить вне сервера. Файл `.env` на сервере тоже не бэкапится в Telegram: секреты (пароли Robokassa, ключи AI и почты) держи в менеджере паролей.
- Бэкап раз в сутки: в худшем случае теряется работа за последние 24 часа.
- Бэкапы на сервере лежат на том же диске, что и данные, поэтому защищают от ошибок и порчи, но не от потери сервера. От потери сервера защищает копия в Telegram.

## Установка таймеров на сервере (один раз, под root)

`deploy.sh` идёт под пользователем `atelier` без sudo, поэтому юниты ставятся вручную: `ssh atelier` (это root), затем:

```
mkdir -p /opt/atelier/backups && chown atelier:atelier /opt/atelier/backups && chmod 700 /opt/atelier/backups
cd /opt/atelier/server/../ && install -m 644 <файлы atelier-monitor.* и atelier-backup.* из deploy/> /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now atelier-monitor.timer atelier-backup.timer
```

Скрипты `set-ops.sh` и `set-admins.sh` кладутся в `/opt/atelier/` (владелец `atelier`, права 755). На боевом сервере всё это уже сделано 19 ноября 2026.

## Если сервер не достаёт до Telegram

DNS может отдавать для `api.telegram.org` адрес, который хостинг не пропускает (так было на боевом сервере 19 ноября: `149.154.166.110` недоступен, `149.154.167.220` работает). Тогда `set-ops.sh` пишет «Нет связи с Telegram» или сам закрепляет рабочий адрес строкой в `/etc/hosts` (`149.154.167.220 api.telegram.org`). Проверка: `curl -sS https://api.telegram.org/botX/getMe` должен вернуть JSON с `Unauthorized`, а не зависнуть. Если когда-нибудь уведомления перестанут приходить, первым делом проверь эту строку и, при необходимости, подбери другой адрес Telegram.

Не проверяй связь корневым адресом `https://api.telegram.org` без пути: он отвечает редиректом на `core.telegram.org`, который может быть недоступен, и это выглядит как таймаут.

## Кто получает уведомления

Уведомления уходят в один чат: `ALERT_TG_CHAT_ID`, его скрипт берёт только из сообщения от указанного ника (по умолчанию `RambleTOT`), чужие сообщения боту игнорируются. Бот ничего не читает и ни на какие команды не отвечает. Дополнительно в @BotFather: `/mybots` → бот → Bot Settings → Allow Groups? → Turn off, чтобы бота нельзя было добавить в группу.
