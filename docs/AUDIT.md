# Аудит Atelier перед MVP

Дата: 7 ноября 2026. Проверено в Chrome (Playwright) на ширинах 390 и 360 px, светлая и тёмная тема, 21 маршрут приложения, плюс лендинг и экран установки. Повторить: `npm run build && node tools/audit.mjs 390` (и `360`).

## Как проверял

| Что | Чем |
|---|---|
| Ошибки консоли, сетевые ошибки, 404 | Playwright, на каждом маршруте |
| Доступность: контраст, имена, aria | axe-core (wcag2a, wcag2aa, best-practice) |
| Зоны нажатия меньше 44 px, текст меньше 11 px, кнопки без имени, горизонтальный скролл | `tools/audit.mjs` |
| Сквозной вход с настоящим сервером (код из письма, синхронизация состояния) | Playwright + `server/` в режиме разработки |
| Серверная часть: вход, лимиты, AI, оплата, подпись уведомлений, удаление | 13 автотестов, `npm run server:test` |
| Вручную глазами | лендинг на 375 и 1280 px, экран установки на Android (с подставленным `beforeinstallprompt`) |

## Что нашёл и исправил

**Ошибки и надёжность**
- На каждом экране гардероба шли запросы за несуществующими PNG (404): теперь запрашиваются только фото демо-вещей.
- Приложение падало белым экраном при ошибке в любом компоненте: добавлена граница ошибок с экраном «Что-то пошло не так» и кнопками «Обновить» и «Сбросить данные».
- «Нет интернета» было только переключателем в демо-панели. Теперь приложение само реагирует на `online` и `offline` браузера, а фото из очереди «Ждёт сеть» дообрабатываются, когда связь вернулась.
- Фото с телефона приходили повёрнутыми (EXIF): исправлено, вырезанное изображение хранится в WebP (в 3–5 раз меньше), поэтому память браузера кончается позже.
- Переполнение хранилища браузера не должно ломать приложение: запись обёрнута, сбои игнорируются.

**Доступность и UX**
- Плитки гардероба, строка прогресса анкеты и скрытое поле кода не имели доступных имён: добавлены.
- Захват панели в конструкторе был меньше 44 px по высоте: сделан 88×44.
- Скрытое поле кода из письма было меньше 16 px: iOS Safari при фокусе увеличивал страницу. Теперь 16.
- Шторки не перехватывали фокус: теперь фокус уходит в шторку при открытии и возвращается при закрытии.
- В «приложении» можно было выделять текст и тянуть картинки как на сайте: отключено везде, кроме полей ввода.
- Раздел «Документы» показывал тост вместо документов: теперь открывает настоящие страницы (`/legal/…`).
- Из подвала профиля убрана строка «прототип».

**Путь пользователя (главное изменение)**
- Лендинг теперь на `/`, приложение на `/app/`.
- Первый экран приложения в браузере телефона: «Поставь Atelier на экран» (iPhone: 3 шага, Android: одна кнопка «Установить»; в Telegram, Instagram, VK и TikTok подсказка, как открыть во внешнем браузере; на компьютере справа от рамки QR-код).
- (Устарело с 11 ноября 2026: гостевой режим убран, вход по почте идёт перед анкетой.) Регистрация была перенесена **после** первой пользы: «Начать» ведёт в анкету без почты, а предложение войти появляется после первого сохранённого образа. Входить обязательно только перед оплатой.
- Проверка включается ссылкой `?demo` (демо-панель, без экрана установки): для показов инвесторам и записи ролика.

## Что в автоматическом аудите осталось

Результат `node tools/audit.mjs 390`: ошибок консоли нет, нарушений axe нет, горизонтального скролла нет. Остались только 3 «маленьких поля ввода» (26 px высотой внутри карточки поля 52 px): это обёртка с большой зоной нажатия, не ошибка.

`npm run lint`: предупреждения вида «`Date.now` в рендере» (3 места: подписка, удаление аккаунта, карточка вещи) и «Fast Refresh» (структура файлов): на работу не влияют, исправить можно позже.

## Чего я не проверял и что нужно проверить руками

Это важно: ниже то, что нельзя настоящим образом проверить без устройства или внешнего аккаунта.

| Что | Почему не проверено | Как проверить |
|---|---|---|
| Установка иконки на **настоящем iPhone** (Safari) | Нет устройства. Я проверил логику показа и тексты | Открыть `https://домен/app/` в Safari, пройти три шага, убедиться, что иконка появилась и открывается без адресной строки |
| Кнопка «Установить» на **настоящем Android** | `beforeinstallprompt` в Chrome приходит только на HTTPS-домене с манифестом и service worker. Я подставлял событие вручную | Открыть в Chrome на Android после выкладки |
| Состояние на iPhone после установки | Хранилище Safari и иконки на экране раздельные (поэтому экран установки стоит первым) | Установить иконку, зайти, войти по почте, убедиться, что гардероб подтягивается с сервера |
| Настоящая оплата CloudPayments | Нужен ваш терминал | `docs/PAYMENTS.md`, шаг 6 |
| Настоящий AI (GigaChat / Yandex) | Нужны ваши ключи | `docs/AI.md` |
| Письма с кодом | Нужна почта SMTP | `docs/DEPLOY.md`, шаг 4 |
| APK на устройстве | Собран, но на телефоне не запускался | `adb install` и пройти приложение |
| Модерация RuStore | Решает RuStore | `docs/RUSTORE.md` |

## Известные ограничения MVP

- Недельный лимит образов считается на клиенте и на сервере (для AI). Лимит фото и избранного считается только на клиенте: пользователь с техническими навыками может его обойти. Для MVP допустимо, перед ростом перенести на сервер.
- Состояние гардероба синхронизируется целым снимком по правилу «последняя запись побеждает». Если человек одновременно правит на двух телефонах, старые правки теряются. Для MVP достаточно.
- Код входа из 4 цифр (как в дизайне) защищён лимитом: 5 попыток на код, 10 минут жизни, не чаще раза в минуту. Если хочешь надёжнее, 6 цифр это правка в двух местах.
- Напоминания и Telegram-бот: в интерфейсе есть переключатели, но уведомления пока не отправляются (нужен отдельный сервис и push).
- Погода в образе пока постоянная для Москвы (+8). Подключить прогноз (Яндекс.Погода, Open-Meteo) нужно через сервер по городу из анкеты.
- Вырезание фона на телефоне даёт хороший результат на светлом ровном фоне. Для сложных фонов подключить rembg (`docs/AI.md`).
