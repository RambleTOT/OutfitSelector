# Задание для агента (Codex или другой кодовый агент с терминалом и Chrome)

Скопируй блок «Промпт» целиком в агента. Остальное, это справка для тебя: что агент сможет сам, а что обязательно делаешь ты.

---

## Промпт

Ты запускаешь продукт **Atelier** (AI-стилист, PWA) в продакшен. Репозиторий: `/Users/rambletot/Atelier`. Сначала прочитай `CLAUDE.md`, `PROGRESS.md`, `docs/TIMEWEB.md`, `docs/DEPLOY.md`, `docs/FLOW_SERVICES.md`, `docs/AI.md`, `docs/PAYMENTS.md`, `docs/AUDIT.md`. Работай по пунктам ниже, по порядку. После каждого пункта пиши в чат коротко: что сделал, как проверил, что дальше.

### Правила работы

1. **Секреты.** Пароли, ключи API, токены, содержимое `.env` никогда не пиши в чат, в коммиты, в логи и скриншоты. `.env` хранится только на сервере (права 600) и на компьютере владельца, файл в git не попадает. Если секрет нужен, попроси владельца внести его самому (см. «Что делает владелец»).
2. **Не делай за владельца** (останавливайся и пиши ему): ввод платёжных данных и платежи, создание аккаунтов и ввод паролей, подтверждение по SMS и почте, прохождение капчи, подписание договоров и согласий, ввод реквизитов ИП в чужие формы, заказ платных услуг без подтверждения суммы. Перед любой покупкой назови сумму и жди явного «да» в чате.
3. **Не угадывай.** Если в документации написано «проверить», проверь в первоисточнике (кабинет, официальная справка) и запиши результат в `PROGRESS.md`. Если не нашёл, скажи об этом, а не придумывай.
4. **Необратимое** (удаление сервера, сброс DNS, перезапись `data/` на сервере, `git push --force`) только после подтверждения владельца.
5. **После каждого пункта:** сборка проходит (`npm run build`), серверные тесты проходят (`npm run server:test`), `git commit` с понятным сообщением, обновлён `PROGRESS.md`.
6. Тексты интерфейса по-русски, на «ты», без точек в коротких фразах. Цвета и размеры только из `src/styles/tokens.css`. Минимальная ширина 360 px, зоны нажатия от 44 px.

### Пункт 1. Подготовка и проверка локально

- `npm install`, `npm run build`, `npm run server:test`: всё зелёное.
- Запусти сервер в режиме разработки (`MAIL_MODE=log`, `STATIC_DIR=../dist`, сборка с `VITE_API_URL=same`) и пройди в Chrome полный путь: лендинг → «Попробовать бесплатно» → экран установки (эмулируй Android и iPhone через DevTools) → «Продолжить в браузере» → «Начать» → анкета → первые вещи → образ → сохранение → шторка «Сохрани свой гардероб» → вход по коду (код смотри в логе сервера) → перезагрузка, данные на месте.
- Заведи найденные ошибки в список, исправь, добавь автотест, если это логика сервера.

### Пункт 2. Домен и сервер (по `docs/TIMEWEB.md`)

Агент делает сам, когда владелец зашёл в кабинеты и отдал управление браузером:
- Проверить свободность домена (кандидаты в `docs/DEPLOY.md`), показать владельцу цену и ждать «да» перед покупкой.
- В кабинете Timeweb Cloud создать сервер по параметрам из `docs/TIMEWEB.md` (Ubuntu 24.04, Москва или СПб, 2 vCPU, 2–4 ГБ, SSH-ключ владельца, бэкапы). Сумму заказа назвать владельцу до нажатия «Заказать».
- В DNS reg.ru добавить записи A для `@` и `www` на IP сервера, проверять `dig`, пока не совпадёт.
- По SSH выполнить шаги 4–8 из `docs/TIMEWEB.md`: пакеты, пользователь, файрвол, nginx, сертификат Let's Encrypt, systemd, выкладка `deploy/deploy.sh`.
- Сделать `node tools/set-domain.mjs <домен> <telegram> <почта>`, собрать юридические страницы (`npm run legal`) с данными из `docs/legal/values.json`, который заполняет владелец.

Готово, когда: `https://домен` отдаёт лендинг с валидным сертификатом, `/api/health` отвечает, вход по настоящему коду из письма работает, с телефона открывается экран установки.

### Пункт 3. Почта для кодов

- Помоги владельцу завести ящик `no-reply@домен` (Яндекс 360 для бизнеса или почта хостинга): добавь TXT и MX-записи в DNS, подскажи включить «пароль приложения». Пароль владелец вносит сам в `/opt/atelier/server/.env` (ты показываешь, какую строку заполнить).
- Проверь: запрос кода отправляет письмо, письмо не попадает в спам (SPF и DKIM в DNS по инструкции почтового провайдера).

### Пункт 4. AI

- Помоги получить ключ GigaChat (developers.sber.ru/studio): ты ведёшь по кабинету, вход и подтверждение делает владелец. **Проверь и запиши в `PROGRESS.md`** условия коммерческого использования бесплатного пакета и что сказано про новых клиентов после 1 сентября 2026 (cloud.ru).
- Скачай сертификат Минцифры на сервер, пропиши `NODE_EXTRA_CA_CERTS`, включи `AI_PROVIDER=gigachat`, перезапусти сервер.
- Проверь `GET /api/config` (`"ai": true`), собери 5 образов из разных поводов, оцени качество. Если модель ломает JSON или повторяется, поправь подсказку в `server/ai/prompt.mjs` и добавь тест.
- Если GigaChat не подошёл, подключи YandexGPT Lite или OpenAI-совместимого провайдера (`docs/AI.md`).
- Бонус: адаптер описания вещи по фото для GigaChat (загрузка файла, затем сообщение с `attachments`) по образцу `describeImage` в `server/ai/providers.mjs`, с тестом на подставной ответ.

### Пункт 5. Аналитика

- Помоги создать счётчик Яндекс.Метрики (владелец входит), номер в `.env.production` как `VITE_METRIKA_ID`, пересобрать, выложить.
- Настрой цели по событиям из кода: `landing_cta`, `gate_view`, `gate_installed`, `gate_skip`, `start_tap`, `register_prompt_accept`, `pay_start`, `pay_success`. Собери воронку «лендинг → кнопка → установка → начать → регистрация».
- Подключи сайт в Яндекс Вебмастере (подтверждение файлом или метатегом в `index.html`), отправь `sitemap.xml`.

### Пункт 6. Оплата CloudPayments

- Помоги владельцу создать **тестовый** сайт в кабинете, пропиши адреса уведомлений из `docs/PAYMENTS.md`. Ключи вносит владелец.
- Проверь круг на тестовом терминале: оплата → тариф включился → отмена подписки → удаление аккаунта. Проверь, что без подписи уведомление получает 401.
- **Боевой терминал и настоящие платежи не трогай**: после подписания договора владелец сам решает и сам делает платёж.

### Пункт 7. Android и RuStore

- Создай релизный ключ командой из `docs/RUSTORE.md`. **Пароль ключа вводит и хранит владелец**, файл `.jks` лежит вне репозитория.
- Собери релиз: `VITE_API_URL=https://домен npm run android:release`. Проверь подпись `apksigner verify`.
- Подготовь карточку RuStore: описание, скриншоты, категория, ссылка на политику. Загрузку в консоль и отправку на модерацию делает владелец (вход через VK ID).
- В `PROGRESS.md` запиши, кто может публиковаться в RuStore (проверь в справке).

### Пункт 8. Контроль качества на живом сайте

- Прогон в Chrome на 390, 360 и 1280 px, светлая и тёмная тема: лендинг, экран установки (эмуляция Android и iPhone), весь путь пользователя, оплата в тесте, офлайн (DevTools → Offline): приложение открывается, гардероб виден.
- Lighthouse для `/` и `/app/` (PWA, производительность, доступность, SEO): цель 90+ по доступности и SEO, исправь найденное.
- `node tools/audit.mjs 390` и `360` на собранной версии: 0 проблем.
- Проверка безопасности: заголовки (`curl -I`), `/api/` без токена даёт 401, нет открытых `/data` и `/.env`, `/api/health` не раскрывает лишнего.

### Пункт 9. Эксплуатация

- Резервные копии по `docs/DEPLOY.md` (cron + снимки диска в Timeweb).
- Проверка доступности (UptimeRobot или аналог): создаёт владелец, ты даёшь адрес `/api/health`.
- Короткий runbook в `docs/RUNBOOK.md`: как смотреть логи, перезапускать, откатываться, где лежат данные, что делать при падении.

### Формат отчёта в конце

Таблица: пункт, статус (сделано, проверено, ждёт владельца, не сделано), как проверил, замечания. Отдельным списком: всё, что владельцу нужно сделать руками, с точными шагами. Отдельным списком: что не получилось проверить и почему.

## Что делает владелец (агент этого сделать не может или не должен)

| Что | Почему |
|---|---|
| Оплатить домен и сервер, пополнить баланс | Платежи и ввод платёжных данных |
| Зарегистрироваться на reg.ru, Timeweb, Яндексе, Sber Studio, CloudPayments, RuStore | Создание аккаунтов, пароли, SMS, капчи |
| Подтвердить владение доменом письмом | Письмо приходит владельцу |
| Подписать договор с CloudPayments, подать реквизиты ИП | Юридически значимо |
| Вписать секреты в `server/.env` (пароль почты, ключи GigaChat и CloudPayments) | Секреты не должны проходить через чат агента |
| Заполнить `docs/legal/values.json` настоящими данными, показать документы юристу | Данные ИП и ответственность |
| Придумать и хранить пароль релизного ключа Android | Потеря ключа означает потерю возможности обновлять приложение |
| Загрузить APK в RuStore Консоль, отправить на модерацию | Вход через VK ID |
| Решения по деньгам: тариф сервера, выбор AI-провайдера, цены подписки | Бюджет |

## Что агент может делать сам, без владельца

Любую работу с кодом и сервером: сборка, тесты, правки, коммиты, SSH-настройка сервера, nginx, сертификаты, systemd, деплой, резервные копии, DNS-записи (когда владелец вошёл в кабинет), прогон в Chrome на нескольких размерах, Lighthouse и axe, настройка Метрики и Вебмастера после входа владельца, подготовка карточки RuStore, исправление найденных ошибок, юридические черновики (без подмены юриста).

## Как подключить агента к браузеру

1. Открой Chrome, войди в нужные кабинеты сам (Timeweb, reg.ru, Метрика). Пароли агенту не нужны.
2. Дай агенту доступ к браузеру (расширение или режим управления Chrome у твоего агента) и скажи, какие вкладки можно трогать.
3. Следи за экраном. Если агент просит ввести пароль, код из SMS или оплатить, делай это сам и возвращай управление.

## Что агент не сможет проверить без реальных устройств

Установку иконки на настоящем iPhone и Android, поведение APK на телефоне, push. Эти проверки на тебе (`docs/AUDIT.md`, таблица «Чего я не проверял»).
