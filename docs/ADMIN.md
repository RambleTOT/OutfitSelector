# Админка

Адрес: `https://atelierai.ru/admin/`. Страница статическая (`public/admin/`, без сборки), данные берёт из `/api/admin/*` (`server/admin.mjs`, маршруты в `server/app.mjs`).

## Вход

Вход только для почт из `ADMIN_EMAILS` в `/opt/atelier/server/.env`. Задать или изменить список:

```
ssh atelier
bash /opt/atelier/set-admins.sh
```

Дальше человек открывает `https://atelierai.ru/admin/`:

1. вводит почту, на неё приходит шестизначный код (5 минут, 5 попыток);
2. на первом входе настраивает приложение-аутентификатор (Google Authenticator, Яндекс Ключ, 1Password): сканирует QR или вводит ключ, подтверждает кодом;
3. сохраняет 10 резервных кодов (показываются один раз, каждый работает один раз);
4. на следующих входах после письма вводит шестизначный код из приложения (или резервный).

Сессия живёт в HttpOnly-cookie, закрывается через 30 минут без действий и через 8 часов в любом случае. «Выйти на всех устройствах» закрывает все сессии. Убранная из `ADMIN_EMAILS` почта теряет доступ сразу.

Потерян телефон и резервные коды: на сервере `set -a; . /opt/atelier/server/.env; set +a; node /opt/atelier/server/admin-cli.mjs reset-2fa почта` (аутентификатор будет настроен заново при следующем входе). Список админов и состояние 2FA: `... admin-cli.mjs list` или страница «Админы» в админке. Сбросить 2FA из самой админки нельзя намеренно.

## Что есть

- Обзор: пользователи (сегодня, за 7 дней, активные), сколько с тарифом (Подписка и Подписка+, у скольких срок на исходе), выручка за месяц и всего (тестовые оплаты Robokassa считаются отдельно и в выручку не входят), график по дням (регистрации, образы, фото), путь пользователя (сайт, регистрация, анкета, вещи, образ, тариф), последние регистрации и платежи, журнал ручных действий.
- Пользователи: поиск по почте и имени, фильтры (с тарифом, Free, Подписка, Подписка+, закончился, ждут ответа), сортировка. Карточка: тариф и срок, выдать тариф на N дней, продлить на 7 и 30 дней, отключить автопродление, снять тариф (сразу Free), обнулить лимиты, активность и вещи, платежи, переписка, удалить аккаунт.
- Платежи: все оплаты с пометкой «Тест» и «Возврат».
- Поддержка: переписки и ответы (то же, что `server/support-cli.mjs`).

## Как работают действия с тарифом

- Выдача вручную: `plan`, `endsAt = сейчас + N дней`, `cancelled: true` (автопродления нет), пометка `manual`. В приложении тариф появится при следующем обращении к серверу.
- «Отключить автопродление» и «Снять тариф» у подписки CloudPayments отменяют и рекуррентный платёж в кассе. Разовые оплаты Robokassa кассе не нужны.
- Все ручные действия пишутся в `db.adminLog` (последние 500) и видны в обзоре и в карточке человека.
- Счётчики «образы» и «фото» на графиках берутся из `events.jsonl` (события `outfit_ok`, `photo_ok`, пишутся с 19 ноября), регистрации из самой базы.

## Безопасность

- Два фактора обязательны: код из письма и код приложения-аутентификатора (TOTP, RFC 6238). Один и тот же код дважды не принимается. 5 ошибок подряд блокируют вход этой почте на 15 минут, срабатывает уведомление в Telegram. Резервные коды хранятся в виде хэшей.
- Почты, которых нет в `ADMIN_EMAILS`, получают тот же ответ, что и админы, но кода не получают: список админов не вычислить перебором.
- Сессия: случайный 256-битный ключ в cookie `HttpOnly; Secure; SameSite=Strict; Path=/api/admin`, в базе только его хэш. JavaScript страницы cookie не видит, поэтому XSS её не украдёт. Защита от CSRF: `SameSite=Strict`, обязательный заголовок `X-Requested-With`, проверка `Origin`.
- Перебор: лимиты на запрос кода, проверку кода и аутентификатора на сервере, плюс `limit_req` в nginx (шаги входа 6 запросов в минуту, остальное 30). IP берётся из `$remote_addr` nginx, подделать заголовком нельзя. Отказы и изменяющие действия пишутся в `journalctl -u atelier-api` (`[admin]`), в журнале действий в админке видно, какой админ что сделал.
- Уведомления в Telegram: каждый вход, блокировка, сброс 2FA (нужен бот, см. `docs/OPS.md`).
- XSS: весь пользовательский текст экранируется (проверено вредоносными значениями), строгая CSP (`script-src 'self'`), `X-Frame-Options: DENY`, `noindex`, `no-store`, `Referrer-Policy: no-referrer` в nginx для `/admin/` (`deploy/nginx.conf`; боевой конфиг на сервере обновляется вручную: nginx в `deploy.sh` не входит).
- Статический токен `SUPPORT_ADMIN_TOKEN` больше не открывает админку. Он остаётся только для `support-cli.mjs` и `admin-cli.mjs` на самом сервере и принимается только с этой же машины (без заголовка `X-Forwarded-For`, который nginx ставит на любой внешний запрос).
- Адрес при регистрации пользователя не может содержать `< > " ' \` & ; ( )`. Входные данные действий проверяются (тариф из списка, срок целым числом 1..3650, идентификатор 24 hex).
- Возможные доработки: ограничение по IP (`ADMIN_IPS`), аппаратные ключи (WebAuthn), отдельные роли (только чтение).

## Тесты

`npm run server:test` (тесты «админка», «вход в админку», «сессия админа»). Стили: `public/admin/tokens.css` копируется из `src/styles/tokens.css` при `npm run build`. QR рисует `public/admin/vendor/qrcode.js` (qrcode-generator, MIT).
