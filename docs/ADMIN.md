# Админка

Адрес: `https://atelierai.ru/admin/`. Страница статическая (`public/admin/`, без сборки), данные берёт из `/api/admin/*` (`server/admin.mjs`, маршруты в `server/app.mjs`).

## Вход

Токен администратора, тот же `SUPPORT_ADMIN_TOKEN` из `/opt/atelier/server/.env`. Посмотреть его (в своём терминале, никому не пересылать):

```
ssh atelier "grep SUPPORT_ADMIN_TOKEN /opt/atelier/server/.env"
```

Токен — часть после `=`. На странице входа есть «Запомнить на этом устройстве», иначе токен живёт до закрытия вкладки. Сменить токен: поправить `.env` и `sudo systemctl restart atelier-api`. Неверный токен: 20 попыток в час с одного адреса, потом 429. Страница закрыта от поисковиков (`noindex`, `Disallow` в `robots.txt`).

## Что есть

- Обзор: пользователи (сегодня, за 7 дней, активные), сколько с тарифом (Подписка и Подписка+, у скольких срок на исходе), выручка за месяц и всего (тестовые оплаты Robokassa считаются отдельно и в выручку не входят), график по дням (регистрации, образы, фото), путь пользователя (сайт, регистрация, анкета, вещи, образ, тариф), последние регистрации и платежи, журнал ручных действий.
- Пользователи: поиск по почте и имени, фильтры (с тарифом, Free, Подписка, Подписка+, закончился, ждут ответа), сортировка. Карточка: тариф и срок, выдать тариф на N дней, продлить на 7 и 30 дней, отключить автопродление, снять тариф (сразу Free), обнулить лимиты, активность и вещи, платежи, переписка, удалить аккаунт.
- Платежи: все оплаты с пометкой «Тест» и «Возврат».
- Поддержка: переписки и ответы (то же, что `server/support-cli.mjs`).

## Как работают действия с тарифом

- Выдача вручную: `plan`, `endsAt = сейчас + N дней`, `cancelled: true` (автопродления нет), пометка `manual`. В приложении тариф появится при следующем обращении к серверу.
- «Отключить автопродление» и «Снять тариф» у подписки CloudPayments отменяют и рекуррентный платёж в кассе. Разовые оплаты Robokassa кассе не нужны.
- Все ручные действия пишутся в `db.adminLog` (последние 500) и видны в обзоре и в карточке человека.
- Счётчики «образы» и «фото» на графиках берутся из `events.jsonl` (события `outfit_ok`, `photo_ok`, пишутся с 19 ноября), регистрации из самой базы.

## Тесты

`npm run server:test` (тест «админка»). Стили: `public/admin/tokens.css` копируется из `src/styles/tokens.css` при `npm run build`.

## Безопасность (аудит 19 ноября)

- Доступ только по токену в заголовке `X-Admin-Token` (не cookie, поэтому CSRF невозможен; CORS заголовок не разрешает). Сравнение за постоянное время, токен короче 16 знаков не принимается. Боевой: 48 знаков, файл `.env` с правами 600.
- Перебор: 20 неудачных попыток в час с адреса на сервере, плюс `limit_req` в nginx (30 запросов в минуту, всплеск 60). IP берётся из `$remote_addr` nginx, подделать заголовком нельзя. Отказы и все изменяющие действия пишутся в `journalctl -u atelier-api` (`[admin]`).
- XSS: весь пользовательский текст (почта, имя, сообщения) экранируется; проверено вредоносными значениями. Строгая CSP (`script-src 'self'`, без inline-скриптов), `X-Frame-Options: DENY`, `noindex`, `no-store`, `Referrer-Policy: no-referrer` заданы в nginx для `/admin/` (`deploy/nginx.conf`, боевой конфиг на сервере обновлён вручную: nginx в `deploy.sh` не входит).
- Адрес при регистрации не может содержать `< > " ' \` & ; ( )`.
- Все входные данные действий проверяются: тариф из списка, срок целым числом 1..3650, идентификатор 24 hex.
- nodemailer обновлён до 10.x (в 6.x были уязвимости), `npm audit` чисто.
- Не закрыто: токен один на всех админов и действия в журнале без имени; смена токена: правка `.env` и `sudo systemctl restart atelier-api`. Двухфакторного входа нет, при росте команды лучше вход по почте с кодом.
