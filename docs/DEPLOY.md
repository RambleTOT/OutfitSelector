# Выкладка Atelier: домен, хостинг, запуск

Цель: человек открывает `https://твой-домен`, видит лендинг, нажимает «Попробовать бесплатно», ставит иконку на экран и дальше пользуется Atelier как приложением.

## Что должно работать на сервере

| Часть | Что это | Где |
|---|---|---|
| Сайт | Статические файлы: лендинг (`/`), приложение (`/app/`), картинки | `dist/` после `npm run build`, отдаёт nginx |
| API | Node.js 20+, один процесс, без базы (JSON-файл), вход по коду, синхронизация, AI-прокси, оплата | `server/`, слушает `127.0.0.1:8787`, nginx проксирует `/api/` |
| Данные | Файл базы, фото вещей, события аналитики | `server/data/`, **делай резервные копии** |

Хватит одного маленького VPS: 1 ядро, 1–2 ГБ памяти, 20 ГБ диска. Это тысячи пользователей на старте.

Если пока нужен только сайт без входа и оплаты (например, показать лендинг и демо), хватит любого обычного хостинга: залить содержимое `dist/` в корень сайта и всё. Лендинг и демо-приложение работают без сервера. API нужен для настоящего входа, синхронизации, AI и оплаты.

## 1. Домен

Покупать на [reg.ru](https://www.reg.ru), аккаунт нужно оформить на ИП или на себя, а в данных владельца писать настоящие данные (иначе домен могут снять).

Свободные имена на 7 ноября 2026, проверено в реестре `.ru` (имена разбирают быстро, проверь ещё раз перед покупкой):

| Домен | Комментарий |
|---|---|
| **atelierapp.ru** | Рекомендую: коротко, читается, понятно что приложение |
| atelier-app.ru | Тот же смысл, дефис мешает диктовать |
| atelierai.ru | Подчёркивает AI |
| atelierstyle.ru, atelierlook.ru, atelier-wear.ru | Запасные |

Заняты: `atelier.ru`, `atelier-ai.ru`, `ai-atelier.ru`, `atelier-style.ru`, `myatelier.ru`, `ateliers.ru`. Цена `.ru` на reg.ru обычно несколько сотен рублей в год, точную цену и акции смотри при заказе.

Важно про название: «Atelier» (ателье) обычное слово, и под ним наверняка есть чужие товарные знаки в классах одежды и ПО. Перед тем как вкладываться в бренд и рекламу, проверь название в реестре Роспатента ([fips.ru](https://www.fips.ru)) или у патентного поверенного.

Что нужно после покупки: **DNS**. В панели reg.ru → домен → «DNS-серверы и управление зоной» добавить записи (IP из шага 2):

```
A     @     <IP сервера>
A     www   <IP сервера>
```

Обновление DNS занимает от минут до пары часов.

## 2. Хостинг

Beget у тебя сломан, вот российские варианты. **Цены ниже ориентировочные, взяты из агрегатора hostinghub.ru и обзоров, не с сайтов самих компаний: проверь на странице тарифа при заказе.**

| Хостинг | Ориентир цены VPS | Плюсы | Минусы |
|---|---|---|---|
| **Timeweb Cloud** | от ~200 ₽/мес | Дёшево, быстрый заказ, много людей на нём сидит, дата-центры в РФ, есть панель и бэкапы | Поддержка бывает медленной в пик |
| **VDSina** | от ~330 ₽/мес | Просто и без лишнего, почасовая оплата | Минимум сервисов вокруг |
| **Reg.ru Cloud** | смотри на сайте | Домен, DNS и сервер в одном месте | Часто дороже аналогов |
| **Selectel** | от ~1 000 ₽/мес | Надёжно, можно закрыть вопросы по 152-ФЗ документами | Дороже на старте |
| **Yandex Cloud** | дороже | Рядом YandexGPT и управляемые базы | Дороже, сложнее |

Мой выбор для MVP: **Timeweb Cloud**, тариф с 1–2 ядрами и 2 ГБ памяти, Ubuntu 24.04, регион Москва или Санкт-Петербург. Позже при росте перенос на Selectel или Yandex Cloud делается за вечер: всё лежит в двух папках.

Для 152-ФЗ нужно, чтобы сервер и данные были в РФ. Это выполняется, если выбран российский хостинг.

## 3. Подготовка сервера (один раз)

Подключись `ssh root@<IP>`. Дальше команды на сервере.

```bash
# обновления и нужные пакеты
apt update && apt -y upgrade
apt -y install nginx certbot python3-certbot-nginx ufw rsync curl

# Node.js 22 LTS
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt -y install nodejs

# отдельный пользователь и папки
adduser --disabled-password --gecos "" atelier
mkdir -p /opt/atelier/server /var/www/atelier
chown -R atelier:atelier /opt/atelier /var/www/atelier
# чтобы deploy.sh мог перезапускать сервис без пароля
echo 'atelier ALL=(ALL) NOPASSWD: /bin/systemctl restart atelier-api' > /etc/sudoers.d/atelier

# файрвол: только ssh и веб
ufw allow OpenSSH && ufw allow 'Nginx Full' && ufw --force enable
```

Положи свой публичный ключ в `/home/atelier/.ssh/authorized_keys`, чтобы заходить как `atelier@<IP>` (`ssh-copy-id atelier@<IP>` с твоего компьютера).

## 4. Настройка

На своём компьютере:

```bash
cp .env.example .env.production           # VITE_API_URL=same, при желании VITE_METRIKA_ID
node tools/set-domain.mjs atelierapp.ru <telegram_поддержки> <почта_поддержки>
cp docs/legal/values.example.json docs/legal/values.json   # и заполни своими данными
npm run legal                              # соберёт оферту, политику, согласие
```

Реквизиты ИП внизу лендинга (`index.html`, блок `foot__req`) впиши вручную. Без реквизитов платёжный сервис сайт не примет.

Серверные настройки: скопируй `server/.env.example` на сервер как `/opt/atelier/server/.env` и заполни (по порядку важности):

1. `TOKEN_SECRET`: `openssl rand -hex 32`.
2. Почта для кодов входа (`SMTP_*`): самый простой путь, завести ящик `no-reply@твой-домен` в Яндекс 360 для бизнеса или у почтового хостинга reg.ru и взять пароль приложения. Порт 465. Без почты вход не работает.
3. `AI_PROVIDER` и ключи: см. `docs/AI.md`. Можно оставить `none`, тогда образы собирает встроенный алгоритм.
4. `CP_PUBLIC_ID`, `CP_API_SECRET`: см. `docs/PAYMENTS.md`. Пока пусто, оплата работает в демо-режиме.

## 5. Первая выкладка

Файл `deploy/nginx.conf` положить как `/etc/nginx/sites-available/atelier` (заменив `your-domain.ru`), `deploy/atelier-api.service` как `/etc/systemd/system/atelier-api.service`:

```bash
ln -s /etc/nginx/sites-available/atelier /etc/nginx/sites-enabled/atelier
rm -f /etc/nginx/sites-enabled/default
systemctl daemon-reload && systemctl enable atelier-api
```

Сертификат (до включения `listen 443` в конфиге временно закомментируй блок с `ssl_*` и сервер `443`, либо используй `certbot --nginx`, он сам правит конфиг):

```bash
certbot --nginx -d atelierapp.ru -d www.atelierapp.ru --agree-tos -m ты@почта.ru
```

Затем с компьютера:

```bash
./deploy/deploy.sh atelier@<IP>
```

Скрипт соберёт сайт, зальёт `dist/` и `server/`, поставит зависимости и перезапустит API. В конце печатает ответ `/api/health`.

Проверка: откройте `https://atelierapp.ru`: лендинг, кнопка ведёт в `/app/`. С телефона на `/app/` должен показаться экран «Поставь Atelier на экран». `https://atelierapp.ru/api/health` отвечает `{"ok":true,...}`.

## 6. Обновления

Любое изменение: `./deploy/deploy.sh atelier@<IP>`. Service worker обновляется сам: пользователи получают новую версию при следующем открытии. Если меняешь кэшируемые файлы оболочки, подними версию `CACHE` в `public/app/sw.js` (`atelier-v2` → `atelier-v3`).

## 7. Резервные копии и мониторинг

Всё, что нельзя потерять, лежит в `/opt/atelier/server/data/` (`db.json`, `photos/`). Простейшая копия раз в сутки:

```bash
# crontab -u atelier -e
17 3 * * * tar czf /home/atelier/backup-$(date +\%a).tgz -C /opt/atelier/server data
```

(копия за каждый день недели перезаписывается). Раз в неделю скачивай файл к себе, а не держи только на сервере. Включи автоматические снимки диска в панели хостинга.

Мониторинг: бесплатно заведи проверку `https://atelierapp.ru/api/health` в UptimeRobot или аналоге и получай письмо, когда сервис упал. Логи: `journalctl -u atelier-api -f`.

Аналитика: событий воронки (`landing_view`, `landing_cta`, `gate_view`, `gate_installed`, `start_tap`, `register_prompt_accept` и др.) пишутся в `data/events.jsonl`. Для быстрого просмотра подключи Яндекс.Метрику: создай счётчик, номер впиши в `VITE_METRIKA_ID`, пересобери. События придут как цели.

## 8. Типичные проблемы

| Симптом | Что смотреть |
|---|---|
| «Нет связи с сервером» при входе | `systemctl status atelier-api`, `curl localhost:8787/api/health`, блок `/api/` в nginx |
| Код на почту не приходит | `journalctl -u atelier-api`, правильность `SMTP_*`, папка «Спам», порт 465 |
| Белый экран на `/app/` после обновления | старый service worker: подними версию `CACHE`, пересобери |
| Оплата прошла, тариф не включился | журнал: «неверная подпись» значит неверный `CP_API_SECRET`; нет строки вовсе: адреса уведомлений в кабинете CloudPayments |
| iPhone не показывает «На экран Домой» | открыто не в Safari, или внутри Telegram/Instagram: экран установки это подскажет |
| Иконка есть, а открывается как вкладка | убедись, что `https://твой-домен/app/manifest.webmanifest` открывается и в нём `"display": "standalone"` |
