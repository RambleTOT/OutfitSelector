# Android-приложение для RuStore

Android-приложение это тот же сайт, упакованный в оболочку Capacitor (WebView). Экраны, логика и стили общие, отдельно поддерживать ничего не нужно. Google Play и App Store пока не используем.

## Что в репозитории

| Что | Где |
|---|---|
| Проект Android | `android/` |
| Настройки оболочки | `capacitor.config.ts` (идентификатор `ru.atelier.app`, название Atelier) |
| Иконки и заставка | `scripts/build-android-assets.mjs` (берёт `public/icons`), запускается после смены иконки |
| Кнопка «Назад», строка состояния | `src/lib/native.ts` |
| Сборка отладочного APK | `npm run android:debug` → `android/app/build/outputs/apk/debug/app-debug.apk` |
| Сборка подписанного релиза | `npm run android:release` (нужен ключ подписи, см. ниже) |

Внутри оболочки лендинг не показывается: страница `/` сразу перенаправляет в `app/`. Экран «Поставь Atelier на экран» тоже скрыт, потому что приложение уже установлено. Пользователь сразу попадает на «Начать». Service worker в APK не регистрируется, файлы лежат внутри приложения и работают без сети.

## Сборка

Нужны JDK 21 и Android SDK (у тебя они уже стоят: `~/Library/Android/sdk`). Адрес API при сборке нужен **полный**, потому что внутри оболочки нет «своего домена»:

```bash
VITE_API_URL=https://atelierapp.ru npm run android:debug
```

Это соберёт сайт, скопирует его в проект Android и соберёт APK. Установить на подключённый телефон (включена отладка по USB): `adb install -r android/app/build/outputs/apk/debug/app-debug.apk`.

На сервере в `server/.env` должно быть `CORS_ORIGIN=https://localhost` (так приложение в оболочке обращается к API; если CORS нужен ещё и сайту на другом домене, список придётся расширить в `server/app.mjs`).

## Подпись для RuStore

Релизный APK/AAB должен быть подписан твоим ключом. Ключ создаётся **один раз** и хранится вечно: потеряешь ключ, не сможешь обновлять приложение.

```bash
keytool -genkeypair -v -keystore ~/atelier-release.jks -alias atelier -keyalg RSA -keysize 2048 -validity 10000
```

Запиши пароли в менеджер паролей, файл `.jks` положи в два надёжных места. **Не клади его в репозиторий.** Потом создай `android/keystore.properties` (в git не попадает):

```
storeFile=/Users/rambletot/atelier-release.jks
storePassword=...
keyAlias=atelier
keyPassword=...
```

и собери: `VITE_API_URL=https://atelierapp.ru npm run android:release`. Готовый файл: `android/app/build/outputs/apk/release/app-release.apk`. Версию (`versionCode`, `versionName`) поднимай в `android/app/build.gradle` перед каждым обновлением: `versionCode` должен каждый раз быть больше предыдущего.

## Публикация в RuStore

Ссылка: [rustore.ru/developer](https://www.rustore.ru/developer) (RuStore Консоль), справка: [rustore.ru/help/developers](https://www.rustore.ru/help/developers).

1. Войти в консоль через VK ID. Добавить новое приложение может пользователь с ролью «Владелец компании». **Проверить в справке до того, как готовить материалы:** кто может быть владельцем компании. По новостям ограничения касались физлиц и самозанятых, нужна организация или ИП. Если ты не ИП, сначала это решить.
2. «Приложения» → «Добавить приложение», загрузить подписанный APK (до 5 ГБ), указать название и описание.
3. Заполнить карточку:
   - **Иконка:** `public/icons/icon-512.png`.
   - **Скриншоты:** `public/icons/shot-*.png` (390×844 → увеличь, если консоль требует другой размер) либо снять заново: `npm run shots`.
   - **Описание:** возьми из блоков лендинга (первый экран, «Как это работает»).
   - **Возрастной рейтинг:** выбрать по анкете консоли (приложение без контента для взрослых).
   - **Категория:** «Стиль жизни» или «Покупки».
4. «Безопасность данных»: указать, что собирается почта, имя, фотографии вещей, данные об использовании; чувствительных разрешений два: интернет и камера. Ссылка на политику конфиденциальности: `https://твой-домен/legal/privacy.html`.
5. Отправить на модерацию. Сроки в справке не указаны, ориентируйся на несколько рабочих дней.

## Чего ждать от модерации (честно)

Приложение-оболочка вокруг сайта это самый частый тип отказов в любых магазинах. Что у нас работает на отказ не в твою пользу:

- есть настоящая работа без сети (гардероб, избранное, конструктор открываются без интернета);
- камера и галерея через системные окна;
- кнопка «Назад» и строка состояния ведут себя как у приложения;
- у приложения есть собственная иконка, заставка и свой экран первого запуска.

Что может вызвать вопросы: тонкая оболочка без «нативных» функций. Если RuStore откажет по этой причине, следующие шаги по стоимости: push-уведомления через RuStore Push SDK (в интерфейсе уже есть переключатели напоминаний) и вход через VK ID. Это отдельный этап работы, в этой версии не сделан.

Ещё одна проверка: в приложении, как и на сайте, должны быть оферта и политика (раздел «Профиль → Документы» открывает их), платёж только через эквайринг, без рекламы в уведомлениях.

## Как вести обновления

1. Поднять `versionCode` и `versionName` в `android/app/build.gradle`.
2. `VITE_API_URL=... npm run android:release`.
3. Загрузить новый APK в консоль → «Версии» → отправить на модерацию.

Сайт обновляется отдельно и мгновенно (`deploy.sh`), но в APK лежит копия сайта на момент сборки. Поэтому для приложения нужен выпуск новой версии, если менялся интерфейс. Серверная часть и данные общие, их менять в APK не нужно.
